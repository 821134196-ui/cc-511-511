# 病区陪护通行码系统

纯 Python 标准库实现（无第三方依赖）：SQLite 保存授权链，本地保存证件遮罩样图，
门禁走模拟适配器，一条命令本地启动。

## 启动

```bash
./run.sh                 # 或 python3 app.py（首次自动灌入演示数据）
python3 app.py --reseed  # 清空并重新生成演示数据
```

打开 http://localhost:8000 ，在登录页选择身份：

| 身份 | 账号 | 能做什么 |
|---|---|---|
| 王慧 / 赵敏 | 护士（A/B 区） | 登记陪护申请、更换陪护、转科、出院；只能处理本病区 |
| 李岚 / 钱静 | 护士长（A/B 区） | 审批发证、转科再评估、病区封控；只能处理本病区 |
| 陈刚 / 刘洋 | 门岗（东/西门） | 仅核验通行码，不能审批人员 |

演示数据自带两条问题样例：**转科样例**（冯德华 A 区→B 区，通行码冻结待评估）与
**丢码样例**（周婷的通行码因手机丢失被即时撤销，再扫会被门岗拦截，启动时会打印该码）。

## 测试

```bash
python3 -m unittest discover -s tests -v
```

覆盖：时段边界（起点含/终点不含、跨夜）、码重放（两个入口并发扫描只放行一次）、
跨病区隔离与角色边界（门岗不能审批）、出院即时撤销，以及限制时段配额、封控、
转科再评估、陪护人更换。

## 规则落点

- **限制陪护时段**（默认 21:00-07:00）每位患者限 1 名陪护，审批发证时校验，超额拒发；
  普通时段每患者最多 2 张有效通行码（`config` 表可调）。
- **即时撤销**：陪护人更换（批准新陪护时旧码作废）、手机丢失、通行码泄露、病区封控、
  患者出院，均立即把通行码置为 `revoked` 并清零在区状态，门岗即刻拦截。
- **转科**：旧授权冻结为 `suspended` 并随患者划入新病区，由新病区护士长重新评估
  （恢复或注销），原病区无权处理。
- **码重放**：入区/离区状态翻转用条件 `UPDATE ... WHERE inside=0 AND status='active'`
  保证原子性，同一码在两个入口同时扫描只放行一次；被拦截的重放也留痕。
- **授权链**：申请→审批→发证→入区/离区→撤销/冻结，每步写入 `events` 表，
  交接看板据此展示。
- **门岗核验页**：大字展示陪护代号、病区与通行结果，拒绝原因完整文字显示；
  姓名、证件号默认遮罩（接口只下发遮罩值），证件样图为本地生成的遮罩 SVG。

## 目录

```
app.py               启动入口（初始化/灌种子/起服务）
run.sh               一条本地启动命令
wardpass/
  db.py              SQLite schema（授权链）与事务助手
  services.py        业务规则：申请/审批/核验/撤销/转科/封控
  gate_adapter.py    门禁模拟适配器（可替换为真实硬件 SDK）
  idcards.py         证件遮罩样图（SVG）生成
  seed.py            演示数据（含转科、丢码样例）
  web.py             标准库 HTTP 层：路由/会话/JSON API/静态页
static/              护士站（按床位）、审批、门岗大字页、交接看板、记录
tests/               unittest：时段边界/码重放/跨病区隔离/出院撤销/流程
data/                运行期生成：wardpass.db 与 id_images/*.svg
```
